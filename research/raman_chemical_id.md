# Deep-learning chemical/material identification from Raman spectra (models, open data, pretrained weights, compute, inference, inputs) — as of 2026-11-06

Scope note: STARCOP/methane and Taiwan-specific datasets are covered by other researchers; only pointers are given here. "Verified" means read from the primary page during this research session; "unverified" means seen only in a search snippet or a third-party page.

## KQ1. The three papers the student cited: dataset, split, accuracy, model size, hardware, code

### Takeaway
All three papers are real, and their numbers are reproduced below, but they use different datasets and split protocols and only one (the 2026 benchmark) releases code and checkpoints. Liu 2017 (Analyst) and DRCNN (RSC Adv. 2022) both use RRUFF subsets, but different subsets and different splits, so their headline accuracies (88.4%/93.3% vs 0.98 top-1) are not directly comparable.

### Cited Findings

**Paper A: Liu et al., "Deep convolutional neural networks for Raman spectrum recognition: a unified solution", Analyst 2017 (DOI 10.1039/C7AN01371J; arXiv 1708.09022, submitted 18 Aug 2017)**
- Authors: Jinchao Liu, Margarita Osadchy, Lorna Ashton, Michael Foster, Christopher J. Solomon, Stuart J. Gibson — [arXiv abstract page](https://arxiv.org/abs/1708.09022)
- Two RRUFF subsets (paper's Table 1): "Ours #1: 1671 classes, 5168 spectra, baseline removal: Yes" (processed RRUFF, "baseline corrected and cosmic rays have also been removed"); "Ours #2: 512 classes, 1676 spectra, baseline removal: No" (raw RRUFF) — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- Split protocol: "we use a leave-one-out scheme to split a dataset into training and test sets. To be specific, for minerals which have more than one spectra, we randomly select a spectrum for testing and use the rest for training." — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- Results on the processed set (Table 2, top-1 ± sd): KNN(k=1) 0.779±0.011; Gradient Boosting 0.617±0.008; Random Forest 0.645±0.007; SVM(linear) 0.819±0.004; SVM(rbf) 0.746±0.003; Correlation 0.717±0.006; CNN 0.884±0.005. CNN top-3 0.953, top-5 0.963. — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- Results on the raw set (Table 3, top-1): raw spectra, no baseline correction: KNN 0.429, GB 0.373, RF 0.394, SVM-lin 0.522, SVM-rbf 0.434, Correlation 0.310, CNN 0.933±0.007. With the best baseline correction (rubber band), KNN reaches 0.825 while CNN drops slightly to 0.911; the paper notes "CNN's performance dropped by about 0.5% ~ 2.5% when combined with baseline correction methods." — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- Architecture: 1-D CNN, "pyramid-shaped convolutional layers for feature extraction and two fully-connected layers for classification", batch norm after each layer, dropout after the first FC layer; details only in Figure 1; parameter count not stated in the text. The 2026 benchmark's re-implementation lists it as LeNet-5-style with three 1-D conv layers (kernels 21, 11, 5), 15.91 M parameters and 21.77 M MACs at input length 1024. — [arXiv PDF](https://arxiv.org/pdf/1708.09022); [Sineesh & Kamsali 2026 HTML](https://arxiv.org/html/2601.16107v2)
- Augmentation: "(1) We shifted each spectrum left or right a few wavenumbers randomly. (2) We added a random noise, proportional to the magnitude at each wave number. (3) For the substances which had more than one spectra, we took linear combinations of all spectra belonging to the same substance". Training: Adam, 50 epochs, lr 1e-3, early stopping. — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- Hardware/time/inference: "Training was performed on a single NVIDIA GTX-1080 GPU. The training time was around seven hours. While for inference, it took less than one millisecond to process a spectrum." Implemented in Keras + TensorFlow. — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- Code/weights: no repository or data-release statement anywhere in the paper text (the only GitHub link is the Keras citation). — [arXiv PDF](https://arxiv.org/pdf/1708.09022)

**Paper B: Zhou, Tang, Qian, Wang, Guo, "Deeply-recursive convolutional neural network for Raman spectra identification", RSC Advances 2022, 12, 5053–5061 (DOI 10.1039/D1RA08804A; submitted 3 Dec 2021, published 10 Feb 2022; CC BY-NC)**
- Landing page — [RSC](https://pubs.rsc.org/en/content/articlelanding/2022/ra/d1ra08804a); full text read via [Europe PMC XML of PMC8981256](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Datasets: (i) KnowItAll (Bio-Rad, commercial) organics: 377 classes, 5,278 spectra after augmentation (wavenumber shift + Gaussian noise), 200–3600 cm-1, 1,024 points; (ii) Zhang et al. target set: 216 spectra of 72 organics (3 per class; 144 for retraining, 72 for test); (iii) RRUFF Dataset_1: 5,292 spectra / 192 classes (classes with >=10 spectra); RRUFF Dataset_2: 8,578 spectra / 1,332 classes (>=2 spectra); RRUFF Dataset_3: 26,479 spectra / 1,322 classes built by copying 4,794 originals to ~20 per class (1,024 points, 0–1700 cm-1). Datasets 1 and 2: 30–1599 cm-1, 1,570 points. — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Split: random stratified 7:3 train/test, then 20% of train for validation (56:14:30). Dataset_1 = 2,964/740/1,588; Dataset_2 = 4,803/1,201/2,574; Dataset_3 = 14,828/3,707/7,944. Adam lr 1e-4, batch 32, 200-epoch cap, early stopping (patience 30), 30 repeated runs averaged. — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Architecture: input 1,024×1; embedding Conv1D(64)→Conv1D(128); one shared recursive Conv1D(128) applied 9 times with supervision branches (256 and 512 filters); reconstruction Conv1D(1,024) → flatten to 65,536 → Dense 1,024 → Dense 512 (dropout 0.5) → softmax; described as a 16-layer network; total parameter count not reported. — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Results (top-1): Dataset_1: Liu-CNN 0.9601, Fan 0.9679, Zhang 0.9583, Sang 0.9772, DRCNN 0.9798. Dataset_2: Liu 0.8309, Fan 0.8368, Zhang 0.8466, Sang 0.8791, DRCNN 0.8818. Dataset_3: Fan 0.6581, Zhang 0.7950, Sang 0.8305, DRCNN 0.8419 (Liu's model "could not produce valid predictions"). Transfer to the 72-organic target set: Zhang DNN 96.4%, Zhang CNN 86.0%, DRCNN 98.1%. No SVM/kNN/correlation baselines. — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Hardware: single NVIDIA GTX Titan, Intel i9-7900X, 256 GB RAM, Keras; no wall-clock time; base model "converged in about 20 epochs"; inference "within milliseconds" (qualitative). — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Code/weights/data: none released; no data-availability statement; RRUFF cited by reference only; KnowItAll is a commercial library ("over 24 000 Raman spectra"). — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML); [RSC landing page](https://pubs.rsc.org/en/content/articlelanding/2022/ra/d1ra08804a)
- Internal inconsistencies flagged by the full-text read: conclusions quote precision values (0.9813, 0.9298) as "accuracy"; the 0.9258 figure for Dataset_3 matches no table cell; "98.1%" does not equal 71/72 (98.6%). — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)

**Paper C: Sineesh & Kamsali, "Benchmarking Deep Learning Models for Raman Spectroscopy Across Open-Source Datasets", arXiv 2601.16107 (v1 22 Jan 2026, v2 28 Jul 2026), published in Digital Discovery (DOI 10.1039/D6DD00044D), CC BY 4.0**
- [arXiv abstract](https://arxiv.org/abs/2601.16107); [HTML v2](https://arxiv.org/html/2601.16107v2); [journal](https://doi.org/10.1039/d6dd00044d)
- Datasets: MLROD (minerals, Horiba LabRAM HR Evolution 532 nm; 89,121 labeled train spectra, 34,903 test after filtering; 15 classes = 12 minerals + 3 1:1 mixtures); Bacteria-ID (Horiba LabRAM HR Evolution 633 nm; 30 isolates × 2,000 reference = 60,000; 100/isolate fine-tune and test = 3,000 each; 30-isolate and 8-treatment tasks); API (Kaiser Raman Rxn2, 785 nm; 3,510 spectra, 32 labels, 31 after merging two identical compounds). Input length 1024 used for parameter/MAC counts. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Models and sizes (params / MACs at length 1024): Deep CNN (Liu 2017) 15.91 M / 21.77 M; SANet (Deng 2021) 2.23 M / 102.48 M; RamanNet (Ibtehaz 2023) 0.72 M / 0.72 M; Transformer (ViT-1D, Liu 2023) 85.17 M / 769.88 M; RamanFormer (Koyun 2024) 4.31 M / 24.33 M; plus Random Forest and SVC (scikit-learn). DRCNN and the Ho 2019 ResNet are NOT in the benchmark. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Protocol: Adam + cross-entropy; grid batch {32,128,512} × lr {1e-3,1e-4,1e-5} (9 configs) selected on validation; 5 independent final runs; up to 40 epochs, early-stopping patience 10. MLROD: 80:20 train/val, official hold-out test. Bacteria-ID: reference 80:20, pretrain then fine-tune at 1/10 lr on the fine-tune split, test on the test split. API: 22 disjoint test samples per class (704), rest 80:20. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Headline numbers (mean ± sd, 5 runs): MLROD overall accuracy: SANet 80.34±0.88, Deep CNN 79.72±1.15, RamanNet 78.3, RamanFormer 78.0, Transformer 72.72, SVC 70.84, RF 69.23; overall macro-F1 best is Deep CNN 0.7132. Bacteria-ID 30-isolate: Deep CNN 85.89±0.12, SANet 85.62, RamanFormer 84.63, RamanNet 84.06, Transformer 83.27, SVC 78.11, RF 58.76; 8-treatment: Deep CNN 97.12. API 32-label: SANet 99.63±0.21, RF 98.66, SVC 97.16, Deep CNN 97.02, RamanFormer 96.85, RamanNet 96.73, Transformer 96.14; 31-identity: SVC and Deep CNN 100.0. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Hardware: NVIDIA RTX A5000, Intel Xeon 3.0 GHz, 64 GB RAM; wall-clock training times are in the SI (not in main text); inference time not reported. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Code: [github.com/asineesh/Benchmark_Raman_DeepLearning](https://github.com/asineesh/Benchmark_Raman_DeepLearning) (MIT; PyTorch; environment.yml; CLI e.g. `python -m train.final_multi_run.Bacteria_ID.thirty.train_RamanNet --batch_size 32 --learning_rate 0.001 --runs 5`). Trained models + logs: [Zenodo 10.5281/zenodo.19701494](https://zenodo.org/records/19701494) — single `logs_models.tar.gz`, 13.9 GB, CC BY 4.0, published 23 Apr 2026, author affiliation Purdue University.

### Inferences
- Liu 2017's "leave-one-spectrum-out per mineral" split means the test set has at most one spectrum per class and the train set often has only 1–2 spectra per class; this is a much harder, more imbalanced regime than DRCNN's stratified 70/30 split on classes with >=10 spectra, which largely explains why DRCNN's RRUFF numbers (0.98) are higher than Liu's (0.88) even though DRCNN also reports Liu's architecture at 0.96 on its own Dataset_1.
- Because Liu 2017 and DRCNN released no code, the "Deep CNN" numbers in the 2026 benchmark come from a re-implementation; they should be cited as "Sineesh & Kamsali's re-implementation of Liu et al." rather than as Liu's own result.

### Gaps
- Liu 2017 Figure 1 (exact filter counts/FC widths) was not extracted (figure-only); the 15.91 M parameter figure is the benchmark's re-implementation, which the benchmark itself notes was reimplemented "from the papers or accompanying TensorFlow code".
- DRCNN parameter count and wall-clock training time are not reported anywhere in the paper.
- Benchmark wall-clock training times live in the Digital Discovery SI, which was not retrieved.

## KQ2. Which results are legitimately comparable, and what the 2026 benchmark found (incl. distribution shift)

### Takeaway
Only results produced under one protocol are comparable: within the Sineesh & Kamsali 2026 benchmark (7 models × 3 datasets, same splits, same tuning budget) and within DRCNN's own table (DRCNN vs four re-implemented CNNs on the same RRUFF splits). Across papers (Liu 2017 vs DRCNN vs Ho 2019 vs benchmark) the datasets, subsets, splits and metrics all differ, so headline accuracies cannot be ranked against each other.

### Cited Findings
- The benchmark's own conclusion: "SANet and Deep CNN demonstrate the strongest performance across the datasets"; the 4.31 M-parameter RamanFormer outperforms the 85 M-parameter ViT-style Transformer, which the authors attribute partly to untuned transformer training choices (warmup, weight decay, schedule) under the shared 40-epoch budget. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Distribution-shift test (MLROD): models trained on clean spectra, tested on clean and 50%-basaltic-dust-contaminated Gabbro and Granite. Gabbro-clean accuracies 81.8–97.8% (Deep CNN 97.77) collapse to 39.76% (SVC) – 48.87% (SANet) on Gabbro-50%-dust; Granite-50%-dust 61.5–84.92%. The paper states "all the models perform substantially worse on the dusty samples" and attributes it to distribution shift rather than overfitting. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Bacteria-ID uses pretrain-then-fine-tune because the fine-tune/test splits have "the same optical-efficiency degradation as the test set"; no ablation without fine-tuning is reported, so the fine-tuning benefit is not quantified in the benchmark. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- API dataset has no distribution shift (train/test same distribution) and all models reach 96–100%. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- The benchmark does not include DRCNN, Ho 2019's ResNet, or RRUFF; it benchmarks "five representative Deep Learning (DL) architectures along with two conventional Machine Learning (ML) methods". — [arXiv abstract](https://arxiv.org/abs/2601.16107)
- DRCNN's comparison table re-implements Liu et al., Fan et al., Zhang et al., Sang et al. on its own three RRUFF subsets, with 30 runs each — a valid within-paper comparison. — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Ho et al. 2019 (original Bacteria-ID paper) reports 82.2±0.3% on the 30-isolate task (logistic regression 75.7%, SVM 74.9%), 97.0±0.3% on antibiotic grouping, clinical 89.0±3.6% pre-trained → 99.0±1.9% after fine-tuning; the benchmark's Deep CNN gets 85.89% on the same 30-isolate test split but under its own tuning protocol. — [Nature Communications](https://www.nature.com/articles/s41467-019-12898-9); [HTML v2](https://arxiv.org/html/2601.16107v2)
- A much larger, independent benchmark exists: RamanBench (Koddenbrock et al., arXiv 2605.02003, v1 3 May 2026, v4 16 Oct 2026, NeurIPS 2026) — 77 datasets, 325,862 spectra, 28 models, fixed 80/20 splits over 3 seeds, single A100. Finding: "no single method dominates"; tabular foundation models (TabPFN v2.5 lowest mean improvability 19.0%; TabICL v2 26.6%; TabPFN v2 30.5%; all others >40%) lead; ReZeroNet is the best non-foundation model; time-series models ROCKET/Arsenal "rank above all gradient boosting methods" on classification; PLS ranks 17th by Elo but has six first-place finishes. Raman-specific models included: Deep CNN, SANet, RamanNet, RamanFormer, RamanTransformer. — [RamanBench arXiv](https://arxiv.org/abs/2605.02003); [HTML v4](https://arxiv.org/html/2605.02003v4)
- A third benchmark-style paper, Soysal et al. 2025 (arXiv 2509.25964, ACS Earth and Space Chemistry 2025), finds on curated RRUFF subsets that compact 1-D CNNs beat k-NN/SVM on handcrafted features without baseline correction; "data splits and scripts" are said to be released. — [arXiv 2509.25964](https://arxiv.org/abs/2509.25964)

### Inferences
- A defensible "best model" claim for a student: on open benchmarks a small 1-D CNN (Liu-style Deep CNN or SANet) is at or near the top on every dataset tested in 2026, while large transformers underperform unless carefully tuned; classical SVC/RF are competitive only on easy, in-distribution tasks (API). RamanBench adds that tabular foundation models (TabPFN) are now the strongest general baseline and must be included in any serious comparison.
- The MLROD dusty-sample results are the clearest open quantification of distribution shift in this domain (roughly a 50-point accuracy drop); it is a within-instrument shift (dust contamination), not a cross-instrument shift.

### Gaps
- Neither benchmark reports a cross-instrument train/test split for the same analytes; RamanBench says its 8-instrument Bioprocess Analytes collection "offers an opportunity for transfer learning" but reports no dedicated cross-instrument experiment.
- Per-model classification leaderboard values in RamanBench (Figure 5) were not extracted; see the live leaderboard at [huggingface.co/spaces/HTW-KI-Werkstatt/RamanBench](https://huggingface.co/spaces/HTW-KI-Werkstatt/RamanBench).

## KQ3. How and on what to train; compute actually used and needed (GPU type, hours, dataset sizes)

### Takeaway
Every published training run in this domain fits on one consumer/workstation GPU: GTX-1080 (~7 h, 2017, 5k spectra with augmentation), GTX Titan (2022), RTX A5000 (2026), A100 (RamanBench). Models are 0.7–16 M parameters, inputs are ~1,000–1,600 points, and datasets are 3k–90k spectra, so a Colab T4-class session is sufficient for a student project; the main constraints are Colab's unpublished, non-guaranteed GPU limits and 12-hour session cap.

### Cited Findings
- Liu 2017: GTX-1080, "around seven hours" for 50 epochs on 5,168 spectra (1671 classes) with shift/noise/linear-combination augmentation. — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- DRCNN: GTX Titan, batch 32, up to 200 epochs with early stopping, 30 repetitions per experiment; base model converged in ~20 epochs. — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Sineesh & Kamsali: RTX A5000, 64 GB RAM; 9 hyperparameter configs × up to 40 epochs + 5 final runs per model–dataset pair; largest dataset 89,121 training spectra (MLROD); model MACs 0.72 M (RamanNet) to 769.88 M (Transformer) per spectrum. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- Ho 2019: ResNet with initial conv (64 filters) + 6 residual blocks × 4 convs (100 filters), 25–26 layers, Adam lr 0.001, batch 10; GPU and training time not reported; dataset 60,000 reference spectra (2,000 per isolate × 30), 381.98–1792.4 cm-1, ~1000-dimensional input, 1 s integration per spectrum. — [Nature Communications](https://www.nature.com/articles/s41467-019-12898-9)
- Bacteria-ID repo notebooks were timed on a "2018 MacBook Pro"; requirements install "no more than 10 minutes"; Python 3.7 / PyTorch 0.4.1 era code. — [GitHub csho33/bacteria-ID](https://github.com/csho33/bacteria-ID)
- RamanNet (Ibtehaz et al.) is described as lightweight enough that "its streamlined structure allows fast training on CPU instead of GPU". — [RSC Advances 2022 PDF via search](https://pubs.rsc.org/en/content/articlepdf/2022/ra/d2ra03722j) (unverified: seen in search snippet only)
- RamanBench: single NVIDIA A100; fixed 80/20 splits, 3 seeds; AutoGluon reference capped at 4 h; dataset sizes range 12 to 130,061 spectra (median 235); feature counts 114–11,689 points (median 1,901); excitation 532–1064 nm. — [HTML v4](https://arxiv.org/html/2605.02003v4)
- Colab: "access to expensive resources like GPUs is heavily restricted" on the free tier; "Colab does not publish these limits"; free notebooks run "at most 12 hours"; "Colab resources are not guaranteed and not unlimited"; GPU types "vary over time". — [Colab FAQ](https://research.google.com/colaboratory/faq.html)
- Augmentation recipes used in the literature: Liu 2017 (random wavenumber shift, proportional noise, random linear combinations of same-class spectra); DRCNN (wavenumber shift + Gaussian noise); Soysal 2025 recommends "controlled noise and amplitude scaling" that preserve peak positions, and shows "tuning a single pooling parameter allows CNNs to absorb Raman shift displacements up to 30 cm-1"; the Sensors 2026 review names "noise injection and GANs" but warns they "often fail to capture the full spectrum of natural sample variability". — [arXiv PDF](https://arxiv.org/pdf/1708.09022); [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML); [arXiv 2509.25964](https://arxiv.org/abs/2509.25964); [Sensors 2026 review via Europe PMC](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12788301/fullTextXML)
- Label efficiency on RRUFF: "Semi-supervised GANs and contrastive pretraining raise accuracy by up to 11% with only 10% of labels"; freezing the backbone and retraining only the softmax layer transfers to unseen minerals "at O(1) cost". — [arXiv 2509.25964](https://arxiv.org/abs/2509.25964)
- Validation pitfalls: the Sensors 2026 review cites Lilek et al. that unstratified K-fold and leave-one-out "can overestimate performance" and recommends leave-one-group-out for multi-site data. — [Sensors 2026 review](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12788301/fullTextXML)

### Inferences
- Arithmetic from the benchmark's MAC counts: a Liu-style Deep CNN costs ~22 M MACs per spectrum; 90k spectra × 40 epochs ≈ 8×10^13 MACs, i.e. minutes on a T4-class GPU (tens of TFLOPS FP16), so even the largest open dataset here trains in well under a Colab session. The 2017 "seven hours" reflects 2017 hardware/frameworks and heavy augmentation, not an inherent cost.
- Ready-made student recipe grounded in the sources: use `pip install raman-data` or the benchmark repo to load Bacteria-ID or the API set (both small enough for CPU prototyping), reproduce the benchmark's Deep CNN/RamanNet with its published hyperparameter grid, then add a TabPFN baseline per RamanBench; use a group-wise (not random) split if any instrument/session metadata exists.

### Gaps
- No paper in this set reports GPU-hours for the full benchmark; Sineesh & Kamsali's wall-clock times are only in the SI.
- No source reports training on a T4/Colab specifically; the sufficiency claim above is an inference from model size and dataset size.

## KQ4. Inference speed per spectrum and compute required

### Takeaway
Published figures are sparse but consistent: sub-millisecond to "milliseconds" per ~1,000-point spectrum for 1-D CNNs on a desktop GPU (2017–2022), with model costs of 0.7–770 M MACs per spectrum; the only concern for deployment is embedded/handheld hardware, which reviews flag as compute-limited.

### Cited Findings
- Liu 2017: "Our method is extremely fast with a processing rate of one sample per millisecond" (footnote: software processing only, excluding spectrometer acquisition); "for inference, it took less than one millisecond to process a spectrum" (hardware context: GTX-1080). — [arXiv PDF](https://arxiv.org/pdf/1708.09022)
- DRCNN: inference "within milliseconds" per spectrum on a GTX Titan (qualitative). — [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Sang et al. (RRUFF CNN, 98.4% accuracy as cited by the Sensors 2026 review) report "millisecond-scale inference", said to suit "in-field and planetary exploration applications". — [Sensors 2026 review](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12788301/fullTextXML)
- Benchmark per-spectrum compute at length 1024: RamanNet 0.72 M MACs; Deep CNN 21.77 M; RamanFormer 24.33 M; SANet 102.48 M; Transformer 769.88 M. Inference time itself is not reported. — [HTML v2](https://arxiv.org/html/2601.16107v2)
- RamanBench reports train+predict runtime only in aggregate; slowest models are MITRA (~626 s per 1K samples) and Arsenal (~2,800 s per 1K); per-model timings are in its Section A.15.2 (not extracted). — [HTML v4](https://arxiv.org/html/2605.02003v4)
- A 2026 Noise2Noise Raman denoising preprint (arXiv 2605.18511) lists 0.019 ms per spectrum for its GPU denoising CNN and 1.11 ms per spectrum for CPU despiking on an RTX 4070 Laptop GPU / 22-core CPU — a denoiser, not a classifier, but the same order of magnitude. — [arXiv 2605.18511](https://arxiv.org/pdf/2605.18511) (unverified: search snippet only)
- Sensors 2026 review: trained DL models "offer rapid inference, making them well suited for real-time detection scenarios", but DL models "have high computational demands, making them difficult to deploy on portable or embedded devices"; handheld meat classification "in just 15 s per sample" (dominated by acquisition). — [Sensors 2026 review](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12788301/fullTextXML)
- Mozaffari & Tay 2020 review of 1-D CNNs for portable Raman explicitly weighs "the potential limit in power consumption and computation ability of handheld systems". — [arXiv 2006.10575](https://arxiv.org/abs/2006.10575)
- Acquisition dominates latency: Ho 2019 used 1 s (SNR 4.1) or 2 s integration per spectrum on a research microscope. — [Nature Communications](https://www.nature.com/articles/s41467-019-12898-9)

### Inferences
- At ~22 M MACs, a Liu-style CNN is ~1,000× cheaper than a ResNet-50 image forward pass; on a laptop CPU (tens of GFLOPS) single-spectrum latency should be a few milliseconds, and on any GPU sub-millisecond batched. Spectrum acquisition (0.1–several seconds on handhelds) will dominate end-to-end time, so model choice should be driven by accuracy/robustness, not speed.

### Gaps
- No peer-reviewed source reports a CPU-vs-GPU latency table for a Raman 1-D CNN classifier; the ~1 ms figure from Liu 2017 is the only concrete classifier number found, and its exact hardware for inference is not separated from training hardware.

## KQ5. Datasets: RRUFF, RamanSPy loaders, Bacteria-ID, and other open Raman sets (URLs, licenses, sizes, classes); Taiwan pointers

### Takeaway
The student's "not many open datasets" claim is outdated: RamanBench/raman-data now index 77–93 public Raman datasets (325,862 spectra) from Zenodo/Figshare/Kaggle/HF/Mendeley, with one-line Python loading; but most sets are small (median 235 spectra), licenses are heterogeneous (CC BY, CC0, BY-NC, Kaggle terms), and RRUFF — the largest mineral library — has no published license and its site is currently gated by a reCAPTCHA that blocks automated bulk download.

### Cited Findings

## KQ6. Published pretrained Raman model weights and spectral foundation models; verifying "no pre-trained public models for everyday chemicals"

### Takeaway
The student's claim is essentially right but needs nuance: no general-purpose public checkpoint exists that identifies arbitrary everyday chemicals from a Raman spectrum; what exists are task-specific checkpoints (Bacteria-ID ResNet; 2026 benchmark checkpoints for minerals/bacteria/pharma compounds), one Hugging Face Space (GEMS) with a built-in but not separately downloadable pretrained encoder, and Raman "foundation model" papers (RSPTE, RamanPFN, DSCF) without located weights — while general tabular foundation models (TabPFN) are the strongest open baseline per RamanBench.

### Cited Findings
- Bacteria-ID repo ships `pretrained_model.ckpt`, `finetuned_model.ckpt`, `clinical_pretrained_model.ckpt` (MIT; PyTorch 0.4.1-era). — [GitHub csho33/bacteria-ID](https://github.com/csho33/bacteria-ID)
- Sineesh & Kamsali release all trained models and logs (Deep CNN, SANet, RamanNet, Transformer, RamanFormer × MLROD/Bacteria-ID/API) as one 13.9 GB tarball, CC BY 4.0, Zenodo 19701494 (published 23 Apr 2026); code MIT. — [Zenodo 19701494](https://zenodo.org/records/19701494); [GitHub](https://github.com/asineesh/Benchmark_Raman_DeepLearning)
- Spec-CNN (MLROD mineral CNN code) on Zenodo 7036374 (code; checkpoint availability not confirmed). — [Zenodo 7036374](https://zenodo.org/record/7036374)
- GEMS (JunhanCai): HF Space "GEMS Generalized Raman Classifier" offers fine-tune and predict workflows and "defaults to the built-in GEMS model if no pretrained model is uploaded"; the author's HF profile lists "None public yet" under models; the dataset card describes Stage-1 pretraining on QMe14S and Stage-2 contrastive learning on RRUFF but links no paper or weights file. — [GEMS Space](https://junhancai-gems-generalized-raman-classifier.hf.space/); [HF profile](https://huggingface.co/JunhanCai); [GEMS dataset card](https://huggingface.co/datasets/JunhanCai/GEMS-Raman-Dataset)

## KQ7. Instrument variability: what the literature says about cross-instrument transfer and mitigations

### Takeaway
"Raman is highly variable across instruments" is well supported: reviews name inter-instrument variability as a top barrier, and the only quantitative cross-spectrometer DL study found (LoRA-CT, Anal. Chem. Aug 2025) shows a model transferred with LoRA (R² 0.952) beats both classical piecewise direct standardization (0.846) and full fine-tuning (0.863) with ~600× fewer trainable parameters; standard mitigations are wavenumber-axis interpolation to a common grid, shift/noise/scale augmentation, pooling for shift tolerance, and fine-tuning/LoRA on a small target-instrument set.

### Cited Findings
- Sensors 2026 review: spectrometer settings affect "SNR, fluorescence background, intensity variability, and spectral drift"; "systematic differences between laboratories and instrumentation" hinder data integration; recommends recording acquisition parameters "to support reproducibility and cross-instrument generalization", "consensus protocols for instrument calibration and data formatting", and leave-one-group-out validation for multi-site deployment. — [Sensors 2026 review](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12788301/fullTextXML)
- Oancea et al. 2026 review (arXiv 2606.14169, 12 Jun 2026, CC BY-SA): barriers are "limited dataset sizes, inter-instrument variability, inconsistent preprocessing, insufficient external validation"; calls for "standardization, robust validation". — [arXiv 2606.14169](https://arxiv.org/abs/2606.14169)
- RamanBench introduction: each measurement setup's optical pathway distorts peaks and baselines; Bioprocess Analytes gives "the same analytes measured across eight different instruments" as a transfer-learning resource. — [HTML v4](https://arxiv.org/html/2605.02003v4)
- LoRA-CT: Lai, Li, Chen, Long, Chen, Lu, Zou, Zhang, "Calibration Transfer of Deep Learning Models among Multiple Raman Spectrometers via Low-Rank Adaptation", Analytical Chemistry, 26 Aug 2025, DOI 10.1021/acs.analchem.5c01846; three datasets (solvent mixtures, blended oils); on the methanol-mixture test set R² 0.952 / RMSE 0.072 vs piecewise direct standardization R² 0.846 / RMSE 0.117 and full-parameter fine-tuning R² 0.863 / RMSE 0.114; "about a 600-fold reduction in trainable parameters"; swappable LoRA modules per instrument; needs "very few transfer samples" (count not in abstract). — [Semantic Scholar record](https://api.semanticscholar.org/graph/v1/paper/DOI:10.1021/acs.analchem.5c01846?fields=title,abstract,year,publicationDate,authors,venue,openAccessPdf); [DOI](https://doi.org/10.1021/acs.analchem.5c01846)
- "Domain-Adaptive Raman Spectral Calibration Transfer for Cross-Instrument Glioma Detection", Analytical Methods 2026: models trained on a master instrument "fail on a slave instrument"; proposes a two-stage network migration separating shared feature learning from target-domain adaptation. — [RSC PDF](https://pubs.rsc.org/en/content/articlepdf/2026/ay/d6ay00651e) (unverified: search snippet)
- Precedent from IR: Mishra et al. "Deep calibration transfer" moves a DL model between infrared instruments by transfer learning. — [record](https://oasisbr.ibict.br/vufind/Record/RCAP_011cbd57f7f020bfcc5758d0e72ce412) (unverified: search snippet)
- Pharma industry view: "spectral library methods, which compare test sample spectra to reference data in a library, are less sensitive to spectral response variations between instruments" than chemometric models. — [American Pharmaceutical Review](https://www.americanpharmaceuticalreview.com/Featured-Articles/131181-Transferring-Raman-Spectral-Libraries-and-Chemometric-based-Methods-Between-Different-Instruments-and-Platforms/) (unverified: search snippet)
- Within-dataset evidence of shift sensitivity: Ho 2019 needed fine-tuning on 100 spectra/isolate acquired under degraded optical efficiency to go from 89.0±3.6% to 99.0±1.9% on clinical isolates; the 2026 benchmark preserves this pretrain/fine-tune protocol. — [Nature Communications](https://www.nature.com/articles/s41467-019-12898-9); [HTML v2](https://arxiv.org/html/2601.16107v2)
- Axis harmonization in practice: the benchmark interpolates MLROD "to a common spectral domain" (processing notebooks) and applies only axis interpolation/trimming and intensity scaling; DRCNN "re-sampled" all databases to 1,024 points and normalized intensities to 0–1. — [GitHub](https://github.com/asineesh/Benchmark_Raman_DeepLearning); [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC8981256/fullTextXML)
- Shift tolerance by architecture: Soysal 2025 — pooling can absorb Raman shift displacements up to 30 cm-1 "trading off translational invariance against spectral resolution". — [arXiv 2509.25964](https://arxiv.org/abs/2509.25964)
- Multi-instrument open data for experiments: adenine SERS interlaboratory study (Zenodo 3572359, in RamanSPy) and raman-data `bioprocess_analytes_*` across Anton Paar (532/785 nm), Kaiser, Metrohm, Mettler Toledo, tec5, Timegate, Tornado. — [RamanSPy docs](https://ramanspy.readthedocs.io/en/latest/datasets.html); [GitHub raman_data](https://github.com/ml-lab-htw/raman_data)
- Excitation wavelength spread in public data (532–1064 nm) changes fluorescence background and intensity response; Bacteria-ID is 633 nm, MLROD 532 nm, API 785 nm, RRUFF multi-wavelength. — [HTML v4](https://arxiv.org/html/2605.02003v4); [HTML v2](https://arxiv.org/html/2601.16107v2)

### Inferences
- A student project that trains on one dataset and tests on another instrument's spectra of the same materials should expect a large drop (the MLROD dust shift alone costs ~50 points); the cheapest robust protocol is: interpolate to a shared wavenumber grid, normalize per spectrum, augment with small shifts/noise/scaling, and hold out an entire instrument or session for validation.
- The raman-data eight-instrument bioprocess set is the only open place found to run a true cross-instrument experiment without owning two spectrometers.

### Gaps
- No open-data study was found that reports classification accuracy of the same DL model across two different Raman instruments on the same classes; LoRA-CT's numbers are regression metrics on closed data.
- Number of target-instrument spectra required by LoRA-CT is in the full text (paywalled).

## KQ8. Practical inputs: handheld/portable Raman (prices), smartphone-coupled spectrometers, and whether NIR or phone cameras can give "chemical makeup" of everyday objects

### Takeaway
Commercial handheld Raman units list at roughly US$35k–50k (Rigaku Progeny US$46,000 list; Metrohm Mira from JPY 5.6 M), with vendor pricing otherwise quote-only; open-source benchtop builds (OpenRAMAN) cost under US$3,500 at ~20–35 cm-1 resolution; a ~US$50 cellphone-camera Raman add-on exists in the literature but with lower SNR and no public dataset. Handheld NIR (not Raman) is the established low-cost route for plastic-type identification of everyday objects, and no source supports obtaining chemical makeup from an ordinary phone RGB camera.

### Inferences
- For a student with no spectrometer, the realistic "inputs" are public spectra; for a small physical demo, the cheapest sourced options are an OpenRAMAN-class build (<US$3.5k, 532 nm, ~20–35 cm-1) or a Plastic-Scanner-class NIR board for plastic typing; commercial handheld Raman is a US$35k+ purchase.
- Nothing found supports "chemical makeup from a phone RGB camera": the cellphone-Raman work still requires a laser, grating and cuvette; without a dispersive element a camera records only colour/texture, so any phone-only "material" classifier would be a visual object classifier, not spectroscopy (this is a reasoning inference; no source directly states it).
- If the broader course project is "chemical and trash detection", NIR-based plastic typing has far more field precedent (recycling sorting) than Raman, while Raman has the richer open benchmark ecosystem.

### Gaps
- No verified street prices for Bruker Bravo, Thermo TruScan G3 or low-end portable Raman units (e.g. B&W Tek, Wasatch, StellarNet, Ocean Insight) were found; vendors sell by quote.
- The Sensors 2025 handheld-NIR plastics paper's data release was not confirmed; the Plastic Scanner dataset licence was not checked.
- No peer-reviewed evaluation of the cellphone Raman device on an open dataset was found; all reports are the inventors' or press.
